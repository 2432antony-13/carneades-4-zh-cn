# 研究贡献与来源说明

版本：0.1

日期：2026-07-27

适用范围：`research/zh-CN`、`docs/zh-CN`、中文示例及后续中国证据推理实现

## 一、项目基础

本项目的代码基础是 [Carneades 4](https://github.com/carneades/carneades-4)。项目保留
上游提交历史、作者信息和 MPL-2.0 许可证，并在其可废止论证能力基础上进行简体中文
本地化及中国证据推理研究。

研究部分综合法律规范、法律论证理论、MoE 和神经符号方法，提出面向中国证据推理的
架构、数据契约、专家路由、事实准入机制和验证方法。具体学术依据在
[研究来源台账](研究来源台账.md)和报告参考文献中列明。

## 二、四类知识的处理规则

| 类型 | 内容 | 本项目的处理 |
|---|---|---|
| 公共规则与事实 | 法律法规、司法解释、官方文件、书目信息、通用技术事实 | 核对权威来源，准确引注；不把规则文本的公共性误写成项目原创 |
| 有归属的理论与技术 | Carneades、MoE、论证型式、批判性问题、神经符号方法 | 使用自己的语言概括，并在首次实质使用处标明作者或来源 |
| 受保护的具体表达 | 论文正文、独创图表、公式编排、案例论证图、具有辨识度的章节结构 | 按照引用规范和许可范围使用 |
| 项目独立成果 | CLES-MoE 的组合架构、数据结构、路由契约、事实门、专家分类和测试方案 | 保留设计说明、来源台账、Git 历史、审计记录和版本变更 |

## 三、来源与项目贡献矩阵

| 构件或主张 | 来源性质 | 本项目的独立工作 | 权利边界 |
|---|---|---|---|
| Carneades 的前提、例外、证明责任和论证评价 | Gordon、Prakken、Walton 等人的既有理论及后续中国法研究 | 选择其作为可废止论证内核，并审查现有 Go 实现与中国证据规则的差距 | Carneades 理论及上游软件分别按其来源归属和许可证使用 |
| 参数级 MoE、稀疏路由 | 1991 年以来的既有机器学习方法 | 将参数专家限制在读取、抽取和候选生成层 | 不主张发明 MoE |
| 细粒度专家和共享专家 | DeepSeekMoE 等已有研究 | 把共享能力转化为所有法律任务必须经过的来源与审计模块 | 属于跨领域设计借鉴，不声称复现 DeepSeek 网络 |
| 双层法律 MoE | 多项既有方法的组合研究 | 区分参数级神经 MoE 与确定性优先的系统级法律专家路由，并规定二者接口和权限 | `CLES-MoE` 名称及具体组合为本项目提出 |
| 事实门 | 来源追溯、人工复核和事实核验的一般思想 | 定义 `candidate/asserted/admitted/disputed/verified/rejected/unknown` 状态及写入权限 | 状态集合、准入规则和与 Carneades 的接口为项目设计 |
| 三本账 | 可审计系统和论证系统的一般思想 | 分离来源账本、事实账本和论证账本，规定各自记录对象和追溯关系 | 三账本在本架构中的组合、字段职责和流转为项目设计 |
| S0、S1 与 E1-E7 专家体系 | 中国证据制度与软件模块化的一般依据 | 设计共享专家、程序专家、证据类型专家、印证专家和法律解释专家的触发与拒绝条件 | 编号、分类、路由规则和输出契约为项目设计 |
| 确定性优先路由 | 规则引擎、分类器和人工复核的既有方法 | 要求法域、程序、阶段、证据类型先由规则路由；神经模型只能建议额外专家 | 路由优先级、冲突停止和人工确认契约为项目设计 |
| 中国证明标准插件方案 | 中国现行法律规则 | 拒绝把 `PE/CCE/BRD` 直接等同中国证明标准，提出资格门与证明力分层接口 | 法律规则不属项目原创；软件映射和插件边界为项目设计 |
| 输出规范与评测体系 | 法律服务可审计性和机器学习评测的一般方法 | 区分已核验事实、主张、争议、缺失和形式结果；设置事实越权、误路由、伪造引用等指标 | 具体输出契约、对照组和零容忍指标为项目设计 |
| 中文电子数据示例 | 中国公开规则和虚构事实 | 使用合成材料独立编写 | 示例不对应真实案件 |

上述“独立”是指具体选择、编排、接口和表达由本项目完成，并不否认其所使用的基础理论、
法律规则和工程方法各有在先来源。

## 四、材料管理

项目材料应当具备清楚的来源、授权或法定使用依据。以下材料进入仓库前需要单独审查：

1. 论文全文、长段落和翻译文本；
2. 论文中的图、表、公式图片和案例论证图；
3. 具有独立表达或编排的改写材料；
4. 不能说明出处和许可状态的数据库、裁判文书批量语料或训练集；
5. 以“汉化”为名删除上游作者、许可证或提交历史的代码副本。

论文题名、作者、期刊、年份等书目信息和研究观点应规范引注。引用法律条文时应标明
发布机关、文件名称、版本和链接。

## 五、独立创作流程

每项研究或实现应按以下顺序留下记录：

1. 在来源台账中登记原始来源、等级和拟支持的主张；
2. 先形成问题清单和系统需求，不以原文目录作为写作提纲；
3. 用项目自己的数据结构、接口、合成案例和测试表达解决方案；
4. 对理论归属、公共规则和项目贡献进行逐项标注；
5. 对交付文本执行来源、引注和许可复核；
6. 通过 Git 提交保留作者、日期和修改内容。

## 六、使用边界

本说明用于展示项目来源和研究贡献，不构成不侵权法律意见。涉及训练数据、论文图片、
付费数据库或真实案件材料时，应根据具体来源、许可条件和发布方式另行完成合规评估。
